Java를 공부하다 보면 가장 자주 접하게 되는 키워드 중 하나가 바로 static이다. 처음에는 단순히 "객체 생성 없이 사용할 수 있는 키워드" 정도로 이해하는 경우가 많지만, 실제로 static은 Java의 메모리 구조와 객체지향 설계를 이해하기 위해 반드시 알아야 하는 중요한 개념이다. 특히 면접에서는 static 변수와 static 메서드의 특징, 메모리 생성 시점, 인스턴스 변수와의 차이점, static 메서드가 인스턴스 변수에 접근할 수 없는 이유 등이 자주 질문된다.

static은 "정적(static)"이라는 의미를 가지며, 객체가 아닌 클래스 자체에 소속되는 멤버를 만들 때 사용한다. 일반적으로 객체지향 프로그래밍에서는 객체를 생성해야 변수나 메서드를 사용할 수 있다. 하지만 static이 붙은 변수나 메서드는 객체 생성 없이 사용할 수 있으며 클래스가 JVM에 의해 로딩되는 시점에 생성된다.

Java의 변수는 크게 지역 변수(Local Variable), 인스턴스 변수(Instance Variable), 클래스 변수(Class Variable)로 나눌 수 있다. 지역 변수는 메서드 내부에서 선언되는 변수로 메서드가 호출될 때 생성되고 종료되면 함께 사라진다. 인스턴스 변수는 객체가 생성될 때 Heap 영역에 생성되며 객체마다 독립적으로 존재한다. 반면 클래스 변수는 static 키워드가 붙은 변수로 클래스가 메모리에 로딩되는 순간 생성되며 프로그램 종료 시까지 유지된다.
``` java
public class Member { 
     static String company = "KOREA"; } 
```
위 코드의 company 변수는 객체마다 생성되는 것이 아니라 클래스 단 하나만 생성된다. 따라서 모든 객체가 같은 값을 공유하게 된다.

``` java
Member m1 = new Member();
Member m2 = new Member();
     System.out.println(Member.company); 
```

객체를 생성하지 않고도 사용할 수 있으며, 모든 객체가 같은 데이터를 공유한다는 것이 static 변수의 특징이다.

이러한 특징 때문에 static 변수는 애플리케이션 전체에서 공통으로 사용하는 값이나 상수를 저장할 때 자주 사용된다. 대표적으로 회사명, 학교명, 설정값, 공통 코드 등이 있다. 특히 변경되지 않는 값은 final과 함께 사용하여 상수로 선언하는 경우가 많다.
``` java
public static final double PI = 3.141592; 
```

실제로 Java의 Math 클래스도 이러한 방식으로 구현되어 있다.

static은 변수뿐만 아니라 메서드에도 사용할 수 있다. static 메서드는 객체 생성 없이 호출할 수 있는 메서드를 의미한다.
``` java
public static int add(int a, int b) {
     return a + b; } 
```
사용 방법은 다음과 같다.
``` java
Calculator.add(10, 20); 
```

객체를 생성하지 않고 클래스 이름으로 바로 호출할 수 있다. 대표적인 예로 Math.max(), Integer.parseInt(), Collections.sort() 등이 있다. 이러한 메서드들은 특정 객체의 상태를 사용할 필요 없이 전달받은 값만으로 동작하기 때문에 static 메서드로 구현된다.

그렇다면 면접에서 가장 자주 나오는 질문 중 하나인 "왜 static 메서드에서는 인스턴스 변수에 접근할 수 없는가?"에 대해 알아보자.

인스턴스 변수는 객체가 생성되어야 메모리에 존재한다.
``` java
private String name; 
```
반면 static 메서드는 객체 생성 여부와 관계없이 클래스가 로딩되는 순간 사용할 수 있다.

``` java
public static void print() { } 
```

만약 static 메서드에서 인스턴스 변수에 접근하려고 한다면 어떤 객체의 인스턴스 변수인지 알 수 없다. 객체가 존재하지 않을 수도 있기 때문이다. 따라서 Java는 static 메서드 내부에서 인스턴스 변수 접근을 허용하지 않는다.

반대로 인스턴스 메서드는 객체가 생성된 이후에 호출되므로 인스턴스 변수와 static 변수 모두 접근할 수 있다.

이 차이를 이해하는 것이 static의 핵심이다. 즉, static은 클래스 수준에서 존재하고 인스턴스는 객체 수준에서 존재한다.

실무에서는 static을 적절히 사용하는 것이 중요하다. 공통 유틸리티 메서드, 상수, 설정 정보 등은 static으로 관리하는 것이 효율적이다. 하지만 모든 것을 static으로 선언하는 것은 좋은 설계가 아니다. static을 과도하게 사용하면 객체지향 설계가 약해지고 전역 상태(Global State)가 만들어질 수 있다. 전역 상태는 코드 간 결합도를 높이고 테스트를 어렵게 만드는 원인이 된다.

따라서 static을 사용할 때는 항상 "이 데이터가 정말 모든 객체가 공유해야 하는 데이터인가?", "이 메서드가 객체 상태를 사용하지 않는가?"를 먼저 고민해야 한다. 만약 특정 객체의 상태와 관련이 있다면 인스턴스 변수와 인스턴스 메서드를 사용하는 것이 올바른 설계이다.

정리하면 static은 객체가 아닌 클래스 자체에 소속되는 멤버를 만들기 위한 키워드이다. static 변수는 클래스가 로딩될 때 생성되어 모든 객체가 공유하며, static 메서드는 객체 생성 없이 호출할 수 있다. 이러한 특징 덕분에 공통 데이터와 공통 기능을 효율적으로 관리할 수 있지만, 남용할 경우 객체지향 설계의 장점을 잃을 수 있다. 따라서 static의 동작 원리와 메모리 생성 시점을 정확히 이해하고 적절한 상황에서 사용하는 것이 중요하다.
